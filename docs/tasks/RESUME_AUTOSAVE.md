# 简历自动保存修复（2026-10-10）

用户指出“自动保存”按钮仍需手动点击，授权补齐真正的自动保存。本轮仅处理简历编辑器保存行为，完成后等待 Claude 独立验收。

## 原因与实现

原代码普通输入只更新 React 状态；“自动保存”实际是手动 PUT 按钮。照片、布局及颜色另有独立写入，存在并发覆盖风险。读取 effect 依赖每次渲染变化的 notify，提示消息可触发重新读取覆盖编辑。

- 载入用户所属简历成功后才开放编辑；初次载入不创建版本，读取失败显示重新加载入口。
- 所有现有编辑字段、模块显隐/顺序、自定义信息、照片、颜色和布局共用自动保存队列；停止编辑 800ms 后调用原 owned PUT。
- 串行写入：请求期间继续修改会保留最新快照并随后写入；不会把旧请求成功误报为最新内容已保存。
- 保存状态常显为等待/正在/已自动保存；失败不标成功，保留编辑状态并提供手动重试，无无限重试。
- 离开编辑器时立即提交待保存内容；刷新/关页存在未保存修改时触发浏览器提示并尝试提交。小请求可使用 keepalive，照片等大请求遵守 fetch 的 keepalive 大小限制。网络失败、强制结束进程仍不能保证保存；本轮没有增加离线草稿或恢复功能。
- GET 不再因提示消息重读。后端权限、版本保存及 AI 数据链不变。
